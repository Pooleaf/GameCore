1. 개요

현재 진행 중인 game map의 전체 지형을 보여주는 지도 아이템을 제작하고, 자기장(WorldBorder) phase가 진행 중일 때는 현재 자기장과 다음 자기장의 위치/크기를 실시간으로 오버레이하여 플레이어에게 전장 상황을 시각적으로 전달한다.

명령어로 즉시 지급할 수 있어야 하고, 기존 StartItem 시스템에 지도 아이템을 시작 아이템으로 추가할 수 있는 옵션을 제공한다.

핵심 가치

  • BR(배틀로얄) 장르 특성상 지형 인지 + 자기장 위치 파악이 게임 흐름의 핵심
  • 관전자 외 일반 플레이어에게 적의 위치 정보가 새지 않아야 함
  • 관리자가 임의 플레이어에게 지급 가능 (테스트/운영 편의)

2. 명령어 사양

항목 값
명령어 /게임 맵 아이템 (alias: /game map item)
일반 플레이어 사용법 /게임 맵 아이템 — 본인에게 지도 아이템 지급
관리자 사용법 /게임 맵 아이템 <플레이어> — 지정 플레이어에게 지도 지급
도움말 노출 중요 도움말(helpCommand)에는 (플레이어) 인자를 표시하지 않는다.
일반 유저에게도 노출되는 명령어이므로 관리자 전용 인자임을 숨긴다.
권한 인자 없음: 권한 없음 (전체 공개)
인자 있음(타 플레이어 지정): GameCorePermission.ADMIN
위치 net.pooleaf.gamecore.commands.MapCommand 에 추가
parent ["맵", "게임 맵"] name ["아이템", "item"]

기존 MapCommand 구조와의 일관성

현재 MapCommand는 모든 서브커맨드를 parent = ["맵", "게임 맵"] 하위로 두고 있어 관리자 명령(생성, 삭제, 목록, 이동 등)과 동일한 패턴으로 등록한다.

단, 기존 서브커맨드는 모두 permission = GameCorePermission.ADMIN이 명시되어 있지만, 아이템은 일반 플레이어에게도 노출되어야 하므로 permission 속성을 생략하고 본문에서 인자 유무에 따라 권한을 직접 분기 처리한다.

명령어 흐름

/게임 맵 아이템 ├─ argumentsLength == 0 → sender 본인에게 지급 └─ argumentsLength >= 1 → ADMIN 권한 체크 ├─ 권한 있음: 지정 플레이어에게 지급 └─ 권한 없음: "해당 명령어를 사용할 수 없습니다" 경고

@Command 어노테이션 예시

@Command(
    parent = ["맵", "게임 맵"],
    name = ["아이템", "item"],
    arguments = "",   // 도움말에서 (플레이어) 인자 숨김
    description = "현재 맵을 보여주는 지도 아이템을 받습니다.",
    color = CommonChatColor.AQUA
    // permission 생략 (일반 플레이어 사용 가능)
)
fun map_item(sender: CommonCommandSender<CommandSender>, result: CommandResult) {
    // 1) 인자 없음 → 본인에게 지급 (Player가 아니면 거부)
    // 2) 인자 있음 → ADMIN 권한 체크 후 대상 플레이어에게 지급
}

3. 기능 요구사항

F-1. 지도 베이스 (지형) 표시

  • 현재 진행 중인 GameCore.currentMap의 전체 worldBorderSize 영역을 128×128 픽셀에 매핑하여 표시
  • 지형 색상은 vanilla 마인크래프트 지도와 동일한 팔레트(MaterialMapColor)를 사용
  • 각 픽셀은 해당 좌표의 최상단 블록(world.getHighestBlockYAt) 색상을 채택

F-2. 자기장 오버레이 (실시간)

  • 현재 자기장: GameMap.currentWorldBorderCenterLocation / currentWorldBorderSize 기준 사각형 테두리 (예: 흰색)
  • 다음 자기장: WorldBorderUpdatePhase가 진행 중인 동안만 표시. phase.getNewWorldBorderSize()로 크기 획득, 점선/빨간색 사각형으로 표시
  • 자기장이 축소/이동 중이면 매 렌더 시점에 최신 값으로 갱신

F-3. 본인 위치 표시

  • 지도 위에 본인 현재 위치를 점(또는 MapCursor의 화살표)으로 표시
  • 다른 플레이어의 위치는 절대 표시하지 않는다 (보안 요구사항 N-1 참조)

F-4. 시작 아이템 통합

  • 기존 StartItemManager / StartItemEditGui에 "지도 아이템" 옵션을 추가
  • 관리자가 시작 아이템 목록에 추가하면, 게임 시작 시 자동 지급

4. 비기능 요구사항 (보안 / 성능)

N-1. 정보 비공개 보안 (Critical)

필수 지도는 게임 시작 시점에 1회 캡처한 정적 스냅샷만 사용한다. 실시간으로 지형/엔티티/플레이어를 다시 스캔해서 그리지 않는다.

이유: 실시간 렌더링 시 플레이어가 이동하지 않고도 다른 플레이어의 행동(블록 변경, 위치)을 지도에서 유추할 수 있다. 이는 BR 장르에서 치명적인 정보 누출이다.

구현 규칙:

  • 게임 시작 시 worldBorder 전체 영역을 1회 비동기 스캔 → byte[16384] 캐싱
  • 이후 모든 렌더는 캐시된 베이스 위에 자기장/본인 위치만 오버레이
  • 다른 플레이어의 위치/이름/방향은 어떤 형태로도 표시 금지
  • vanilla MapView의 기본 렌더러는 반드시 제거 (다른 플레이어 커서 자동 노출 방지)

N-2. 성능

  • 스냅샷 캡처는 메인 스레드에서 블록 접근(1.8 World API는 not thread-safe) — 청크 단위로 쪼개거나 delay를 끼워 분산
  • worldBorderSize 200 기준 약 40,000 블록 스캔 → 1초 내 완료 목표
  • MapRenderer.render()는 매 틱 호출되므로 베이스 픽셀 복사는 System.arraycopy 수준으로 최소화
  • MapPalette.matchColor() 결과는 모두 상수로 사전 계산

N-3. 메모리

  • 스냅샷 크기: 128 × 128 = 16,384 byte ≈ 16KB / 맵 1개
  • 모든 플레이어가 동일한 스냅샷 인스턴스를 공유 (플레이어별 복제 금지)

5. 기술 설계

T-1. 블록 → 지도 색상 매핑 방식

NMS MaterialMapColor 직접 호출 방식 채택.

하드코딩 RGB 테이블 대신, vanilla 마인크래프트가 사용하는 색 테이블을 그대로 가져온다. 이미 프로젝트는 ProtocolLib 등으로 NMS 의존이 허용된 패턴이며, 1.8.9 (v1_8_R3)에 해당 API가 분명히 존재한다. 

// 의사 코드
val nmsBlock = CraftMagicNumbers.getBlock(material)
val iBlockData = nmsBlock.fromLegacyData(data.toInt())
val mapColor = iBlockData.block.g(iBlockData)  // obfuscated: getMapColor
val brightness = 2  // 0=darkest, 3=brightest
val paletteByte = (mapColor.M * 4 + brightness).toByte()  // M: colorIndex

장점: vanilla와 동일한 색감, 색상 테이블 노가다 불필요. 단점: v1_8_R3 obfuscated 이름 의존.

T-2. 데이터 구조

class GameMapSnapshot(
    val baseColors: ByteArray,      // 128*128 = 16384, 지형 베이스
    val centerX: Double,            // 스냅샷 기준 월드 중심 X
    val centerZ: Double,            // 스냅샷 기준 월드 중심 Z
    val worldBorderSize: Int        // 스냅샷 시점의 맵 최대 크기
)

T-3. 좌표 → 픽셀 매핑

val blocksPerPixel = worldBorderSize / 128.0
val worldX = centerX - worldBorderSize / 2 + (px + 0.5) * blocksPerPixel
val worldZ = centerZ - worldBorderSize / 2 + (py + 0.5) * blocksPerPixel

T-4. 렌더 파이프라인 (매 틱)

render(map, canvas, player): 1. baseColors (스냅샷) → canvas 전체 페인트 2. 현재 자기장 사각형 오버레이 (WHITE) 3. WorldBorderUpdatePhase 진행 중이면 다음 자기장 사각형 (RED) 4. player.location → 픽셀 변환 → 본인 위치 점 (YELLOW) 5. cursors는 본인 화살표만 add (다른 플레이어 제거)

T-5. 신규 파일 구조

net.pooleaf.gamecore.map/
  ├─ GameMapItem.kt           # 지도 ItemStack 생성/지급 헬퍼
  ├─ GameMapSnapshot.kt       # 스냅샷 데이터 클래스 + 좌표 변환
  ├─ GameMapSnapshotService.kt # 게임 시작 시 스냅샷 캡처 로직
  ├─ GameMapRenderer.kt       # MapRenderer 구현체 (오버레이 그리기)
  └─ NmsMapColor.kt           # NMS MaterialMapColor 래퍼

net.pooleaf.gamecore.commands/
  └─ MapCommand.kt            # /게임 맵 아이템 서브커맨드 추가

6. 기존 코드 연동 포인트

대상연동 내용
GameMap currentWorldBorderCenterLocation / currentWorldBorderSize / centerLocation / worldBorderSize 읽기 전용 참조
WorldBorderUpdatePhase getNewWorldBorderSize(), updateRemainingSeconds, updateDurationSeconds 참조하여 "다음 자기장" 오버레이 결정
PhasePipeline 현재 phase가 WorldBorderUpdatePhase 인스턴스인지 확인하는 진입점
Game / GameManager 게임 시작 시점(StartCountPhase 완료 직후 ~ GodModePhase 진입 전)에 스냅샷 캡처 트리거
StartItemManager / StartItemEditGui / StartItem "지도 아이템" 타입을 시작 아이템으로 추가 가능하도록 enum/팩토리 확장
MapCommand 아이템 서브커맨드 추가 (parent: ["맵", "게임 맵"]). 도움말 표시는 인자 없는 시그니처만
GameCorePermission 관리자 인자 사용 시 ADMIN 권한 체크

7. 리스크 및 검증 계획

R-1. NMS 의존 (v1_8_R3)

MaterialMapColor의 obfuscated 필드/메서드 이름(g(), M)은 매핑에 따라 달라질 수 있다. Paper 1.8.8 빌드의 obfuscation 매핑이 표준 v1_8_R3인지 사전 확인 필요.

검증 PoC: 다음 한 줄을 게임 시작 시 1회 실행해 성공/실패 로그 확인

val grassColor = NmsMapColor.get(Material.GRASS)
Logger.log("grass map color byte = $grassColor")

R-2. 청크 미로드 영역

worldBorder가 매우 크고 SlimeWorld가 lazy load되는 경우, 스냅샷 캡처 시 청크가 강제 로드되며 부하 발생. 필요 시 worldBorderSize 상한을 두거나, 캡처 진행률을 관리자에게 표시하는 안을 고려.

R-3. 다른 플레이어 커서 자동 노출

vanilla MapView는 같은 mapID를 든 모든 플레이어의 화살표를 자동 표시한다. 이를 방지하려면 (1) 기본 vanilla 렌더러 제거 + (2) MapRenderer.render()에서 canvas.cursors를 본인 것만 add 하도록 명시.

R-4. MapID 관리

Bukkit.createMap()는 호출마다 새 mapID를 발급한다. 게임마다 새로 만들거나, 1개 고정 mapID를 재사용하는 방식 중 선택. 재사용 시 mapview.world 등 상태 관리 주의.

권장: 게임 시작 시점에 새 mapID를 발급해 사용 → 게임 종료 시 폐기 (구현 단순)

본 문서는 구현 착수 전 합의된 요구사항/설계 기준선이다. 구현 중 발견되는 제약은 본 문서에 반영하여 갱신한다.
