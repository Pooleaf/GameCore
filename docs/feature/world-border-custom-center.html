1. 개요

game-core의 월드보더 시스템이 맵 원본 중심(GameMap.centerLocation)이 아닌 별도의 자기장 중심 좌표를 사용할 수 있도록 확장한다.

구체적으로는 GameMap에 이미 선언만 되어 있고 사용되지 않던 currentWorldBorderCenterLocation 필드를 실제 자기장 중심 좌표로 활용한다. GameMapService.updateWorldBorder가 이 필드를 읽어 worldBorder.center로 사용하고, WorldBorderUpdatePhase의 파티클 표시도 이 필드를 기준으로 그린다.

"게임마다 자기장 위치를 다르게" 같은 정책은 본 모듈이 결정하지 않는다. ability-core 같은 게임 모드 구현체가 게임 시작 시 이 필드를 세팅하면 game-core는 그 좌표로 자기장을 그려준다.

2. 문제 정의

  • 현재 모든 자기장 단계는 GameMap.centerLocation(맵 원본 중심)을 기준으로 줄어든다.
  • 그 결과 자기장이 줄어들면서 최종적으로 모이는 위치가 매 게임 항상 동일하다.
  • 게임 모드 구현체가 게임마다 자기장 중심을 바꾸고 싶어도, game-core API가 이를 허용하지 않는다.
  • 한편 GameMap에는 currentWorldBorderCenterLocation 필드가 정의되어 있으나 어디서도 참조되지 않는다.

3. 마인크래프트 월드보더 제약

본 기능의 설계는 다음 제약 위에서 결정되었다.

  • 월드보더는 정사각형이며 월드당 1개만 존재한다.
  • 중심 좌표 변경은 즉시 반영된다(보간 없음). 자기장이 줄어드는 도중에 중심을 바꾸면 자기장이 순간이동하듯 옮겨진다.
  • 크기 변화는 setSize(size, duration)으로 선형 보간이 가능하지만, 중심에는 동일한 보간 API가 없다.

따라서 PUBG 식으로 "맵 전체에서 시작해 다른 한 점으로 자연스럽게 수렴"하는 연출은 바닐라 월드보더로 불가능하다. 이 한계를 받아들이고 자기장 중심은 게임 시작 시 한 번만 정해지고 게임 내내 고정되는 모델을 따른다.

4. 범위

포함

  • GameMap.currentWorldBorderCenterLocation 필드를 실제 자기장 중심으로 활용한다.
  • GameMapService.updateWorldBorder의 두 오버로드가 이 필드를 사용해 worldBorder.center를 설정한다.
  • GameMapService.initWorldBorder는 호출 시점에 currentWorldBorderCenterLocation을 centerLocation으로 초기화한다.
  • GameWorldBorderChangeEvent.centerLocation이 currentWorldBorderCenterLocation 값으로 전달된다.
  • WorldBorderUpdatePhase의 파티클 표시가 currentWorldBorderCenterLocation을 기준으로 그려진다.

제외

  • "게임마다 자기장 중심을 어떻게 정하는가"라는 정책은 본 모듈에서 결정하지 않는다.
  • 자기장 크기 단계(현재 2/3, 1/3, 20) 자체는 변경하지 않는다.
  • 리플레이 모듈은 변경하지 않는다(자세한 이유는 7. 리플레이 호환성 참조).
  • 자기장 중심을 좌표 후보 리스트에서 뽑는 등의 고급 정책은 본 범위에 포함하지 않는다.

5. 기능 요구사항

ID 요구사항 상세
FR-1 중심 좌표 보관 GameMap은 현재 자기장의 중심 좌표를 currentWorldBorderCenterLocation에 보관한다. 기본값은 centerLocation과 동일하게 동작한다.
FR-2 초기화 동작 initWorldBorder(map) 호출 시 currentWorldBorderCenterLocation은 centerLocation으로 리셋된다. 모드가 별도로 세팅하지 않으면 기존 동작과 완전히 동일하다.
FR-3 월드보더 적용 updateWorldBorder의 두 오버로드는 worldBorder.center로 currentWorldBorderCenterLocation(혹은 그 fallback인 centerLocation)을 사용한다.
FR-4 이벤트 일관성 GameWorldBorderChangeEvent.centerLocation은 실제 적용된 자기장 중심 좌표를 그대로 전달한다.
FR-5 파티클 일관성 WorldBorderUpdatePhase.startParticleTimer가 그리는 다음 자기장 미리보기 파티클은 실제 자기장 중심(currentWorldBorderCenterLocation)을 기준으로 한다.
FR-6 좌표 검사 일관성 GameMap.isInWorldBorder는 currentWorldBorderCenterLocation을 기준으로 자기장 안/밖을 판정한다. isInMap은 맵 원본 영역을 판정하므로 centerLocation을 그대로 사용한다.
FR-7 외부에서의 중심 갱신 모드 구현체가 currentWorldBorderCenterLocation을 직접 세팅할 수 있어야 한다(예: internal set → 모듈 외부에서도 가능한 가시성으로 조정). 별도 setter 메서드를 제공해도 된다.
FR-8 안전한 폴백 currentWorldBorderCenterLocation이 null인 경우 centerLocation으로 자동 대체한다. 둘 다 null이면 기존과 동일하게 예외를 던진다.

6. 기술 설계

변경 1 — GameMap

currentWorldBorderCenterLocation 필드의 가시성을 외부 모듈에서 세팅 가능한 수준으로 조정한다. 부가적으로 isInWorldBorder가 이 필드를 사용하도록 수정한다. 

// GameMap.kt (변경 후 의도)

@ConfigExclude
var currentWorldBorderCenterLocation: Location? = null
    // 모드 구현체가 세팅 가능하도록 가시성을 외부 모듈에 허용한다.
    // 예: public set 또는 dedicated setter

fun isInWorldBorder(location: Location, worldBorderSize: Int = currentWorldBorderSize): Boolean {
    val center = currentWorldBorderCenterLocation ?: centerLocation ?: return false
    return location.world.equals(center.world)
            && Math.abs(center.x - location.x) <= worldBorderSize / 2
            && Math.abs(center.z - location.z) <= worldBorderSize / 2
}

변경 2 — GameMapService.initWorldBorder

자기장 초기화 시 자기장 중심 또한 맵 원본 중심으로 리셋한다. 이로써 모드가 별도로 세팅하지 않으면 기존 동작과 완전히 동일하다. 

fun initWorldBorder(map: GameMap) {
    map.currentWorldBorderSize = map.worldBorderSize
    map.currentWorldBorderCenterLocation = map.centerLocation
    updateWorldBorder(map, map.currentWorldBorderSize)
}

변경 3 — GameMapService.updateWorldBorder (두 오버로드 모두)

worldBorder.center와 이벤트 발행 시 사용하는 좌표를 모두 currentWorldBorderCenterLocation(없으면 centerLocation)으로 통일한다. 

fun updateWorldBorder(map: GameMap, newSize: Int) {
    val center = map.currentWorldBorderCenterLocation ?: map.centerLocation
        ?: error("centerLocation cannot be null")

    val beforeSize = map.currentWorldBorderSize
    val worldBorder = center.world.worldBorder
    worldBorder.center = center
    worldBorder.size = newSize.toDouble()
    worldBorder.damageBuffer = 0.0

    map.currentWorldBorderSize = newSize

    try {
        Bukkit.getPluginManager().callEvent(
            GameWorldBorderChangeEvent(center, beforeSize, newSize, 0)
        )
    } catch (exception: Exception) {
        exception.printStackTrace()
    }
}

fun updateWorldBorder(map: GameMap, newSize: Int, updateSizePerSeconds: Int): Int {
    // 동일하게 currentWorldBorderCenterLocation을 우선 사용
    ...
}

변경 4 — WorldBorderUpdatePhase.startParticleTimer

현재는 map.centerLocation을 기준으로 다음 자기장 영역을 파티클로 그리고 있다. 이를 currentWorldBorderCenterLocation 기준으로 변경한다. 

val centerLocation = map.currentWorldBorderCenterLocation ?: map.centerLocation!!
val newWorldBorderSize = getNewWorldBorderSize()

val startX = (centerLocation.x - (newWorldBorderSize / 2)).toInt()
val endX   = (centerLocation.x + (newWorldBorderSize / 2)).toInt()
val startZ = (centerLocation.z - (newWorldBorderSize / 2)).toInt()
val endZ   = (centerLocation.z + (newWorldBorderSize / 2)).toInt()

호출 흐름

[게임 시작] GameCore.unsafe.mapService.initWorldBorder(map) -> map.currentWorldBorderSize = map.worldBorderSize -> map.currentWorldBorderCenterLocation = map.centerLocation (기본값 리셋) -> updateWorldBorder(map, map.worldBorderSize) [모드 정책 적용 (선택)] ability-core 등의 GameStartedEvent 리스너가 map.currentWorldBorderCenterLocation = (게임 랜덤 중심) 으로 덮어쓴다. [자기장 단계 진행] WorldBorderUpdatePhase -> updateWorldBorder(map, newSize, sizePerSec) -> worldBorder.center = map.currentWorldBorderCenterLocation -> worldBorder.setSize(...) -> GameWorldBorderChangeEvent(center=게임 중심, ...) -> startParticleTimer -> 게임 중심 기준으로 다음 자기장 파티클 표시

7. 리플레이 호환성

game-replay 모듈은 본 변경에 대해 수정이 필요 없다.

GameWorldBorderChangeDataRecordListener는 GameWorldBorderChangeEvent.centerLocation의 x, z 좌표를 그대로 기록하고, GameWorldBorderChangeDataReplayHandler는 기록된 중심 좌표를 기준으로 파티클을 그린다. 즉, 리플레이는 맵 중심을 직접 참조하지 않고 이벤트가 전달한 중심 좌표만 신뢰하므로 본 변경이 그대로 호환된다.

옛 리플레이 파일을 재생할 때에도 그 당시 기록된 중심 좌표가 그대로 사용되므로, 이전 게임과 중심이 다른 새 게임이 동일한 재생기에서 정상 표시된다.

8. 사용처 연동 가이드

본 모듈은 메커니즘만 제공한다. 게임별 중심 결정 정책은 모드 구현체에 위임한다.

일반적인 사용 패턴

// 게임 시작 시점 (예: ability-core의 GameStartedEvent 리스너)
@EventHandler
fun onGameStarted(event: GameStartedEvent) {
    val map = GameCore.currentMap ?: return
    val newCenter = computeGameCenter(map)  // 모드별 정책으로 계산
    map.currentWorldBorderCenterLocation = newCenter

    // 이후의 자기장 단계(WorldBorderUpdatePhase)는 자동으로
    // newCenter를 기준으로 줄어든다. 추가 호출 불필요.
}

세팅 시점은 GameStartedEvent가 적절하다. 해당 이벤트는 플레이어가 맵에 텔레포트 되기 전, 그리고 1차 WorldBorderUpdatePhase가 시작되기 한참 전에 발행되므로 안전하다.

모드 구현체가 지켜야 할 규약

  • 중심 변경은 자기장이 줄어들기 시작하기 전(혹은 단계 사이의 안정 구간)에 수행해야 한다. 줄어드는 도중에 바꾸면 자기장이 순간이동한다.
  • 중심 좌표는 같은 월드여야 한다(centerLocation.world와 일치).
  • 중심을 맵 영역 밖으로 너무 멀리 두면 자기장이 맵 밖으로 삐져나간다. 이 검증은 모드 구현체가 책임진다.
  • 게임 종료 후 새 게임을 시작할 때 모드 구현체가 다시 세팅하지 않으면 initWorldBorder가 자동으로 맵 중심으로 리셋한다.

9. 리스크 및 검증 계획

자기장이 줄어드는 도중에 중심을 변경하면 즉시 순간이동한다. 모드 구현체는 단계 전환 시점이나 시작 시점에만 중심을 바꿔야 한다. 이 규약 위반에 대한 가드는 본 모듈에서 강제하지 않는다.

자기장 중심이 맵 영역 밖에 가까우면 자기장이 슬라임 월드의 미생성 청크 영역까지 침범할 수 있다. 각 모드 구현체는 자체적으로 안전 범위를 보장해야 한다.

검증 항목

  • 모드가 currentWorldBorderCenterLocation을 세팅하지 않은 경우, 자기장 동작이 기존과 완전히 동일한지 확인한다.
  • 모드가 게임 시작 시점에 중심을 다른 좌표로 세팅하면, 모든 자기장 단계가 그 좌표를 기준으로 줄어드는지 확인한다.
  • WorldBorderUpdatePhase의 파티클이 세팅한 중심을 기준으로 표시되는지 확인한다.
  • GameWorldBorderChangeEvent 구독자(특히 game-replay)가 세팅한 중심 좌표를 정확히 수신하는지 확인한다.
  • 게임 재시작(initWorldBorder) 시 currentWorldBorderCenterLocation이 centerLocation으로 정상 리셋되는지 확인한다.
  • 리플레이 녹화 → 재생 시 자기장 중심이 녹화 시점과 동일한 좌표로 그려지는지 확인한다.
  • isInWorldBorder가 새 중심을 기준으로 판정하는지(자기장 밖 데미지 처리 등이 정상 작동하는지) 확인한다.
